# DESSERT-004 — Adaptive Revenue Simulator

Offline only. Run `node experiments/dessert-004/run.mjs` to reproduce 1000 scenario rows and results. Seed 20261127. Same financial conventions as DESSERT-003 (integer kurus, refunded revenue removed, costs retained); this simulator is a separate aggregate model, not an actual POS integration. No production data. No live tracking. No changes to main, PR #527 or public runtime.

Scenarios independently draw synthetic demand and cost parameters with seeded pseudorandom streams; arms share per-session random draws for paired comparisons. 400–3000 sessions, base cake conversion 2–12%, relative effect -35% to +70%, other-dessert probability 8–30%, substitution fraction 0–100%, cake price 190 TRY (catalog), cake variable cost 65–170 TRY, other dessert price 100–240 TRY, cost ratio 30–80%, cake refunds 0–12% plus treatment shift -2.5 to +7 percentage points (clamped), other refunds 0–10%, per-treatment session cost 0–1.50 TRY, fixed activation cost 0–150 TRY. These distributions are illustrative assumptions, not estimated from customers. One dessert or no purchase per session, full refunds only. No basket complements, taxes, capacity, customer return or seasonality model. Positive and negative effects included. A and B show fixed control and story; adaptive runs balanced random 40% pilot then selects B for remaining sessions only if estimated incremental contribution per session minus 1.645 standard errors is positive, otherwise A. Minimum 30 per pilot arm. Pilot expense included; activation cost is sunk after pilot. Threshold is an illustrative one-sided normal risk heuristic, not a validated confidence guarantee; no future outcomes used in choice. No policy tuning on results. All 1000 scenarios validated against count, revenue and contribution conservation, exposure and policy invariants. 19 separate stress/rejection/reproducibility checks. No CI claimed. Results normalized to TRY per 1000 eligible sessions, equally weighted across scenarios; totalMargin is pooled absolute contribution, not an uplift probability or real forecast.

See `qa/evidence/dessert-004/results.json` and `qa/evidence/dessert-004/scenarios.csv` for full evidence. Evidence is intentionally stored in the repository's existing QA directory, excluded by the public integrity-manifest generator. Source and tests executed together in isolated JS runtime before commit; Node CI and browser integration not run.
