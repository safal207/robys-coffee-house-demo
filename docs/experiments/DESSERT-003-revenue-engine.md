# DESSERT-003 — offline Revenue Experiment Engine

Prototype only, disabled by default, no site imports, no real tracking or POS calls. Run `node experiments/dessert-003/revenue-engine.test.mjs`.

Assignment uses injected secure random 128-bit hex token and injected session storage; first byte is split equally across arms. Invalid or unavailable storage fails closed (ordinary menu outside experiment). Session registration is intention-to-treat. Stage counters are unique per session. This is not a unique-person count; concurrent tabs and repeat sessions remain a limitation. Receipt reconciliation accepts only normalized, versioned records from a future authenticated POS adapter, not client-reported payment. Order tokens are immutable across sessions. Pending or abandoned QR contributes no revenue; cancelled/refunded orders can retain unrecovered costs. Partial refunds use the latest normalized fulfilled record with remaining cake units and basket net revenue. Amounts are integer kurus; contribution is net revenue minus supplied variable costs, not total business profit. No actual costs or payment records supplied. Ledger is in-memory and not a production database. Live enablement, secure randomness integration, session allocation before rendering, control UI, durable server-side ledger, POS authentication, reconciliation window, privacy review, and browser/CI acceptance remain required.

Contract checks run in a JS isolate using the same functions as the committed test: 25 passed. GitHub CI not run by this test. Synthetic 1000 sessions per arm, 50 vs 65 paid cake orders at 190 TRY, 95 TRY assumed variable cost: +2850 TRY net revenue and +1425 TRY contribution, not an observed result.
