# Order selection sharing: bounded integration

## Product boundary

This change adds an optional, collapsed sharing disclosure to the existing order
review. Menu and Smart Choice continue to use the same order store. The primary
next action remains **Show the barista**; the sharing disclosure is hidden in that
view. No photo, catalog price, recommendation, intro animation or native Android
implementation is replaced.

The disclosure previews every item and approved option, quantity, unit price,
line amount and total. Telegram and copying are explicit secondary actions. The
recipient can edit the message; the menu link does not reconstruct the basket on
another device. Neither action means cafe receipt, acceptance, payment or stock
confirmation. This is not a Telegram bot or Mini App.

The sharing projection resolves products through the existing canonical resolver
and checks its sum against the order-store summary. Unknown products, inconsistent
quantities/totals, pending legacy migration and empty orders cannot yield a partial
share. Oversized links retain the complete copyable text instead of truncating it.
Clipboard denial has a selectable fallback. Delayed clipboard completion cannot
acknowledge a newer order as already copied. Rendering performs no clipboard or
Telegram request and does not mutate the order.

## Reproduce and review

```sh
npm ci --no-audit --no-fund
npm run check
npm run verify:security
git diff --exit-code
npx playwright install --with-deps chromium
npm run test:order-share:browser
node scripts/guest-journey-browser.mjs
```

The new read-only **Order selection sharing** workflow runs the browser suite
and the existing enforced mobile/desktop Lighthouse profile commands, including
for the stacked PR base. Existing Visual regression remains independent. The
browser report, source/runtime hashes and screenshots are uploaded together;
Lighthouse uploads its raw reports and gate status. Reports name the tested Git
head; local modified-tree evidence additionally names the runtime hashes.

The original #346 / #345 native Android boundary remains unresolved by this
change. Merge, deployment, physical devices, real Telegram-client compatibility
and conversion improvement are not claimed. Review this as a dependent draft PR,
not as authorization to merge its parent.
