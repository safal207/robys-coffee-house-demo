# Android callback deadline repair — 8 September 2026

## Result and scope

Late native callbacks could certify bridge readiness or handoff completion after
their time budget had expired, if delivery preceded an overdue timeout Runnable.
The repair checks the absolute deadline inside both callbacks. It preserves the
3,500 ms bridge budget, 1,500 ms visual budget, 48 ms polling, fallback and retry UI.

This is a confirmed callback classification defect, not an explanation or cure
for the separately observed GPU/presentation delay. Rejecting a late callback
does not make a busy UI thread deliver a timer on time. Android remains HOLD in
[#345](https://github.com/safal207/robys-coffee-house-demo/issues/345).

Base is PR #346 head `7799f80b5a6561beec57f2d98f8e8ca58e8c36fa`.
The repair is isolated on `fix/android-handoff-deadlines-20260908`; it does not
include the unpromoted product-frame or early-styles experiments. No web runtime,
generated asset, capture assertion or release threshold changes.

## Source change

`MainActivity.pollBridgeReady` already checked expiry before submitting JavaScript,
but the later result callback accepted `ready` without checking again. The result
callback now checks expiry after generation and URL validation. An expired result
uses the existing bridge-timeout fallback immediately, even for a non-ready value.

The visual request now records an absolute deadline before calling
`postVisualStateCallback`. Completion validates generation, terminal state and URL
before checking that deadline. At or after expiry it follows the existing visual
timeout/error path and cannot release the web handoff or dismiss the cover.
Starting a new load resets the deadline. Timely completion remains unchanged.

The delayed visual timeout remains scheduled after the request returns. The new
callback guard measures its budget from request initiation. Neither check can
execute while the main thread is blocked; this patch makes no stronger scheduling
or presentation guarantee.

## Differential evidence

The same runner and fixtures compile the entire actual `MainActivity.java` on
Java 17, without editing its bytes. Minimal Android/AndroidX doubles control
`SystemClock`, the Handler queue and WebView result delivery. They contain no
handoff state machine. The harness drives the real lifecycle and callbacks,
including retry through the error view's real click listener.
